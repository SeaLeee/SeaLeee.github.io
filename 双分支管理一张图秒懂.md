# 🎯 一张图看懂双分支管理

```
┌─────────────────────────────────────────────────────────────┐
│                      你的工作流程                             │
└─────────────────────────────────────────────────────────────┘

1️⃣ 写文章                    2️⃣ 部署网站                 3️⃣ 保存源码
   ↓                            ↓                           ↓
hexo new "文章"             hexo clean                  git add .
   ↓                       hexo generate                git commit
编辑 .md 文件               hexo deploy                 git push origin source
   ↓                            ↓                           ↓
hexo server (预览)          推送到 main 分支             推送到 source 分支


┌─────────────────────────────────────────────────────────────┐
│                     GitHub 仓库结构                           │
└─────────────────────────────────────────────────────────────┘

                SeaLeee/SeaLeee.github.io
                        │
        ┌───────────────┴───────────────┐
        │                               │
    source 分支                      main 分支
    (源码仓库)                      (网站仓库)
        │                               │
        ├── README.md                   ├── index.html
        ├── .gitignore                  ├── 404.html
        └── new-blog/                   ├── 2025/10/01/文章/
            ├── _config.yml             │   └── index.html
            ├── package.json            ├── css/
            └── source/                 │   └── main.css
                └── _posts/             ├── js/
                    └── 文章.md  ←─┐   │   └── boot.js
                                    │   └── img/
                                    │       └── avatar.png
                                    │
                         hexo generate 转换
                                    │
                                    └→ HTML + CSS + JS


┌─────────────────────────────────────────────────────────────┐
│                      关键区别                                 │
└─────────────────────────────────────────────────────────────┘

特性          │  source 分支          │  main 分支
─────────────┼──────────────────────┼───────────────────
文件类型      │  Markdown、YAML、JSON │  HTML、CSS、JS
文件大小      │  小（几十 KB）        │  大（几百 KB）
可读性        │  ★★★★★（人类可读）   │  ★★☆☆☆（机器代码）
谁使用        │  你（编辑文章）       │  GitHub Pages（展示网站）
更新方式      │  手动 git push        │  hexo deploy 自动
需要克隆吗    │  ✅ 需要（写作必备）  │  ❌ 不需要（自动生成）


┌─────────────────────────────────────────────────────────────┐
│                    类比：做蛋糕                               │
└─────────────────────────────────────────────────────────────┘

source 分支 = 配方和原料
  📝 配方.txt（Markdown 文章）
  🥚 鸡蛋、面粉、糖（配置文件）
  👨‍🍳 你可以随时修改配方

          ↓ hexo generate（烤箱）
          
main 分支 = 成品蛋糕
  🎂 烤好的蛋糕（HTML 网站）
  📦 装在盒子里（CSS/JS）
  👥 顾客直接享用（访客访问）


┌─────────────────────────────────────────────────────────────┐
│                    记忆口诀                                   │
└─────────────────────────────────────────────────────────────┘

source 存源码，main 放网站
写完文章记得，两边都要传
hexo deploy 很智能，main 它自己管
git push source 别忘记，源码安全最重要


┌─────────────────────────────────────────────────────────────┐
│                    实战检查清单                               │
└─────────────────────────────────────────────────────────────┘

每次发布文章后，检查：

□ 网站能访问吗？
  → 访问 https://SeaLeee.github.io
  → 能看到新文章 ✅

□ main 分支更新了吗？
  → 自动更新（hexo deploy 完成）✅

□ source 分支更新了吗？
  → 需要手动：git push origin source ⚠️
  
□ 源文件备份了吗？
  → 检查 GitHub source 分支 ✅


┌─────────────────────────────────────────────────────────────┐
│                    故障排查                                   │
└─────────────────────────────────────────────────────────────┘

问题：网站没更新
  → 检查 hexo deploy 有没有报错
  → 访问 GitHub 查看 main 分支的提交时间

问题：换电脑后找不到文章源文件
  → 检查有没有 push 到 source 分支
  → git clone -b source 下载源码

问题：不知道当前在哪个分支
  → 运行 git branch 查看
  → 应该在 source 分支（* source）


┌─────────────────────────────────────────────────────────────┐
│                    最佳实践                                   │
└─────────────────────────────────────────────────────────────┘

✅ DO（推荐）
  • 每天开始前：git pull origin source
  • 写完文章后：hexo clean && hexo g -d
  • 部署完成后：立即 git push origin source
  • 定期备份：每周查看 source 分支是否最新

❌ DON'T（不要）
  • 不要手动修改 main 分支（会被覆盖）
  • 不要在 main 分支工作
  • 不要忘记 push source 分支
  • 不要克隆 main 分支（没用）


┌─────────────────────────────────────────────────────────────┐
│                    总结：一句话理解                           │
└─────────────────────────────────────────────────────────────┘

source 是你的工作台（Markdown 文章 + 配置）
main 是展示橱窗（HTML 网站）
hexo deploy 是搬运工（自动从工作台搬到橱窗）
你需要做的：写好文章，两边都保存！

┌─────────────────────────────────────────────────────────────┐
│                    5 分钟快速上手                             │
└─────────────────────────────────────────────────────────────┘

# 1. 克隆源码（首次）
git clone -b source https://github.com/SeaLeee/SeaLeee.github.io.git
cd SeaLeee.github.io/new-blog
npm install

# 2. 写文章
hexo new "我的新文章"
# 编辑 source/_posts/我的新文章.md

# 3. 预览
hexo server

# 4. 发布
hexo clean && hexo g -d

# 5. 保存源码
cd ..
git add .
git commit -m "新增文章"
git push origin source

完成！🎉
```
